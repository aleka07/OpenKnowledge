01 · Хранилище

Пять таблиц, вся система

-- точка интеграции: сюда пишет offline, отсюда читает online
evidence (
  id            uuid PK,
  source        text,           -- meeting | doc | obsidian | archive | code
  source_id     text,           -- для файлов = content_hash; для митингов = id транскрипта
  unit          text,           -- whole | episode | chunk | page
  unit_ord      int,            -- порядковый номер единицы внутри объекта
  raw_ref       text,           -- путь в raw store
  content       text,           -- нормализованный документ (артефакт дистилляции)
  extracted_text text,          -- сырой текст единицы ДО дистилляции
  embedding     vector(N),      -- HNSW; N = размерность модели (Qwen3-Emb: 0.6B→1024, 4B→2560, 8B→4096)
  tsv           tsvector,       -- GIN по (extracted_text || content): exact search видит сырьё
  meta          jsonb,          -- people, project, refs, mime
  occurred_at   timestamptz,    -- когда знание возникло → age decay
  indexed_at    timestamptz,
  embedding_model  text,        -- смена модели = переиндексация, не тихая каша векторов
  pipeline_version text,        -- «что пересчитывать после смены промпта» = SQL-запрос
  superseded_by uuid NULL,
  UNIQUE (source, source_id, unit, unit_ord)
)

-- реестр блобов: физическая идентичность = хэш содержимого
raw_objects (
  content_hash  text PK,        -- sha256; дубль в 10 папках = 1 строка, обработка 1 раз
  mime          text,
  bytes         bigint,
  path          text,           -- raw/{hash[:2]}/{hash}/original.*
  first_seen    timestamptz,
  kind          text            -- readable | scan | image | other (см. роутинг)
)

-- вхождения: логическая идентичность = файл в источнике (может меняться независимо)
source_objects (
  source        text,
  external_id   text,           -- drive fileId | путь на NAS | id транскрипта
  content_hash  text FK,        -- какой blob сейчас за этим файлом
  path          text,
  modified_at   timestamptz,
  deleted_at    timestamptz NULL,
  PRIMARY KEY (source, external_id)
)
-- файл изменился → новый hash у того же (source, external_id) → superseded_by старым evidence

-- очередь backfill и ретраев; инкрементальный режим её тоже использует
ingest_jobs (
  id            bigserial PK,
  content_hash  text,
  stage         text,           -- normalize | distill | embed
  priority      int,            -- 0 incremental, 5 readable, 10 scan, 20 image
  status        text,           -- pending | processing | done | failed | skipped
  attempts      int,
  next_attempt_at timestamptz,  -- backoff между ретраями
  locked_by     text,           -- lease: умерший воркер не вешает job навсегда —
  lease_until   timestamptz,    --   просроченный lease возвращает job в очередь
  filter_policy text,           -- версия политики skip: пересмотр порога = перезапуск, не археология
  error         text,
  updated_at    timestamptz
)

api_tokens (token_hash, name, created_at, revoked_at)
query_log  (ts, token_name, tool, query, top_ids)

Две идентичности, не одна: raw_objects — дедуплицированный blob (хэш), source_objects — вхождение файла в источник. Переименование меняет только source_objects; изменение содержимого связывает новый хэш со старым логическим файлом и корректно ставит superseded_by. Для митингов source_id остаётся id транскрипта.

02 · Маршрутизация типов

«Разные файлы» — это три разных пайплайна

Классификация происходит один раз, на инвентаризации, и пишется в raw_objects.kind. Детект скана: pdfminer извлёк < 100 символов на страницу → текстового слоя нет → это скан.

kindЧто этоNormalizeПриоритет
readable docx, xlsx, pptx, md, txt, PDF с текстовым слоем MarkItDown → converted.md → чанки по заголовкам → distill 0 — первая волна, за сутки-двое
scan PDF без текстового слоя постранично через VLM: pdf → PNG страниц → каждая страница = один запрос → merge в markdown → дальше как readable 10 — фоном, догоняет неделю
image jpg, png, фотографии — в v3 не обрабатываются: индексируются имя + путь в meta. «Найти файл» работает, «поиск по содержимому фото» отложен 20 — status=skipped
other архивы, exe, неизвестное — status=skipped с указанием причины —
Пути — это метаданные, не смысл. В архиве имена вида «Копия Копия отчёт_final2 (3).docx» и хаотичная вложенность. Никакой логики, извлекающей смысл из имён и структуры папок: первичны хэш и содержимое, путь просто фиксируется в source_objects.
03 · Батчинг vLLM

16–32 запроса в полёте, а не по одному

vLLM делает continuous batching на своей стороне — задача клиента просто держать очередь запросов полной. Воркеры шлют запросы асинхронно, конкурентность ограничена семафором и подбирается под конфиг vLLM (16 или 32 — смотреть на GPU-утилизацию и ttft).

Inference endpoints: один процесс vLLM = одна модель

# «gateway» — это конфиг воркера, не отдельный сервис:
ENDPOINTS = {
  "generation": "http://localhost:8000/v1",   # Qwen3.5-35B NVFP4 — distill
  "embedding":  "http://localhost:8001/v1",   # Qwen3-Embedding (--runner pooling)
  "vlm":        "http://localhost:8002/v1",   # VLM для OCR сканов (фаза backfill)
}
# семафор — свой на каждый endpoint; OCR-волна не выедает конкурентность у distill
# общий паттерн для distill, embeddings и VLM-OCR
sem = asyncio.Semaphore(CONCURRENCY)          # 16–32, из конфига, per endpoint

async def call_llm(unit):
    async with sem:
        return await client.chat(model, messages=prompt(unit))

# gather — в пределах ОДНОГО документа (десятки units), не по всему backfill:
artifacts = await asyncio.gather(*[call_llm(u) for u in doc_units])

# эмбеддинги — нативный батч одним запросом:
embs = await client.embeddings(model, input=[a.content for a in batch_64])

Асимметрия Qwen3-Embedding: документ без инструкции, запрос — с ней

# OFFLINE (ingest-воркер): документы эмбеддятся БЕЗ префикса
emb_doc = embed(artifact.content)

# ONLINE (MCP-сервер): запрос оборачивается в инструкцию задачи
TASK = "Дан вопрос о рабочих документах, митингах и проектах команды; \
найди фрагменты, отвечающие на него"
emb_query = embed(f"Instruct: {TASK}\nQuery: {q}")
# забыть префикс = тихая деградация retrieval на ~1-5%, тестом не ловится, только eval'ом
# размерность vector(N) и embedding_model в evidence должны совпадать с фактической моделью

PDF-сканы: страница = запрос

# скан не идёт в VLM целиком — режется постранично
pages = pdf_to_png(scan_path, dpi=200)          # pdftoppm / pymupdf
tasks = [vlm_ocr(page) for page in pages]       # 1 страница = 1 запрос
mds   = await asyncio.gather(*tasks)            # 30-страничный скан = 1-2 батча
markdown = merge(mds)                            # склейка с маркерами страниц
# → converted.md в raw store → дальше штатный путь: чанки → distill → embed
  • Изоляция ошибок — битая страница фейлит одну задачу, не весь документ; страница уходит в ретрай, документ собирается из остальных с пометкой в meta.
  • Прогрев равномерный — семафор общий на воркер, поэтому OCR-волна не выест конкурентность у дистилляции митингов: у инкрементальных задач приоритет выше.
  • Маркеры страниц — в merged markdown остаются <!-- page 7 -->: get_raw потом может отдать конкретную страницу, и цитата адресуема.

Контракты вызовов и валидация выхода

У двух типов вызовов к vLLM разные контракты. Невалидный выход никогда не доходит до insert в evidence — он умирает в job'е со статусом failed, конвейер идёт дальше.

OCR-вызов (сканы)Distill-вызов (артефакты)

Гарантия формата—guided decoding: JSON-схема передаётся в запрос, семплер не может сгенерировать невалидный JSON
Проверка воркеромэвристики: страница не пустая, длина правдоподобна, нет дегенерации (повтор токена по кругу)pydantic: схема, непустые обязательные поля, типы
Не прошлоретрай страницы ×3 → страница помечена битой в meta, документ собирается из остальныхретрай ×3 → ingest_jobs.status=failed с текстом ошибки
# guided decoding — параметр запроса, НЕ режим сервера: рестарт vLLM не нужен,
# обычные запросы не замедляет; первая новая схема компилируется секунды, потом кэш
resp = await client.chat.completions.create(
    model="qwen3.5-35b",
    messages=prompt(unit),
    extra_body={"guided_json": ArtifactSchema.model_json_schema()}
)
art = ArtifactSchema.model_validate_json(resp.choices[0].message.content)  # рубеж 2
  • Prefix caching — включить на сервере --enable-prefix-caching: system-промпт дистилляции одинаков на тысячах чанков, кэш префикса заметно ускоряет backfill.
  • Честная граница валидации: она ловит сломанный формат, но не фактическую ошибку в валидном формате (VLM неверно прочёл цифру в плохом скане). Предохранители от этого — eval-набор и прослеживаемость через raw_ref до оригинала.
04 · Backfill

Архив 9 000 файлов: очередь, не cron

Инкрементальный воркер рассчитан на ручеёк. Разовая волна идёт другим режимом: сначала дешёвая инвентаризация всего дерева, потом воркеры разгребают очередь батчами. Упал на 4 000-м — продолжил с 4 001-го.

Фаза 1 — инвентаризация (часы, без LLM)

for path in walk("/mnt/nas/archive"):
    h = sha256(path)
    source_objects.upsert("archive", path, h)    # вхождение фиксируем всегда
    if h in raw_objects: continue               # дубль до байта — работу не делаем
    kind = classify(path)                        # readable | scan | image | other
    raw_store.put(h, path)                       # копия оригинала по хэшу
    ingest_jobs.insert(h, stage="normalize",
                       priority=prio(kind), status="pending")

Фаза 2 — разгребание очереди (сутки — неделя, с LLM)

# bounded producer/consumer: N воркеров, память не растёт с размером архива.
# claim атомарный, с lease — умерший воркер не вешает job:
--   UPDATE ingest_jobs SET locked_by=$w, lease_until=now()+'10 min'
--   WHERE id = (SELECT id FROM ingest_jobs
--               WHERE status='pending' AND next_attempt_at <= now()
--                  OR (status='processing' AND lease_until < now())  -- вернулся из мёртвого lease
--               ORDER BY priority, id LIMIT 1
--               FOR UPDATE SKIP LOCKED)                              -- воркеры не дерутся
--   RETURNING *;

async def worker(w):                             # запускается N штук (2-4)
    while job := claim(w):                       # SQL выше; долгий job продлевает lease
        try:
            obj  = raw_objects[job.content_hash]
            md   = normalize(obj)                # MarkItDown | VLM постранично
            arts = await distill_batch(split(md)) # gather в пределах документа
            embs = await embed_batch(arts)
            db.upsert_evidence(arts, embs)
            job.done()
        except Exception as e:
            job.fail(str(e))                     # attempts+1, next_attempt_at с backoff; после 3 — failed
# ядовитый файл (битый PDF, запароленный docx) не останавливает конвейер

Что получаем на выходе

  • Отчёт по завершении: сколько done / failed (с причинами) / skipped; сколько дублей схлопнулось. Ожидаемо: из 9k файлов уникальных останется ~6–7k.
  • Порядок готовности: readable-документы ищутся через сутки-двое; сканы въезжают фоном до недели; поиск работает всё это время по мере наполнения.
  • Оценка объёма: ~100–300k строк evidence. Для Postgres+HNSW это малый размер — запас по масштабу минимум два порядка.
  • Узкое место — inference, не БД: при 2–4 чанках/сек с батчингом дистилляция ~100k чанков — это 8–14 часов чистого GPU-времени.
  • После backfill тот же источник переключается в инкрементальный режим: обход по mtime > watermark, новые файлы идут через ту же очередь.
05 · Инкрементальный ingest

Живые источники: ручеёк по таймерам

# один воркер на источник, systemd timer; митинги — по watch, немедленно
for item in source.changed_since(watermark):
    h = sha256(item)                             # 1. дедуп до любой работы
    source_objects.upsert(src, item.id, h)       # 2. вхождение — всегда; изменённый файл
    if seen(h): continue                        #    получает новый hash у того же external_id
    path = raw_store.put(h, item)                # 3. оригинал
    md   = normalize(item)                       # 4. MarkItDown / VLM / passthrough
    units= split(md)                             # 5. эпизоды | чанки | страницы
    arts = await distill_batch(units)            # 6. фильтр внутри: IDF, длина, resolution;
                                                 #    skip пишется в jobs с filter_policy —
                                                 #    raw хранится, пересмотр порога = перезапуск
    embs = await embed_batch(arts)               # 7. без Instruct-префикса (документы!)
    db.upsert_evidence(arts, embs, path)         # 8. идемпотентно; старой версии → superseded_by
    advance(watermark)                           # только после успеха

08 · Retrieval

Гибрид + RRF + decay; reranker выключен до замеров

  • Full-text (GIN) — по extracted_text || content, т.е. видит сырой текст до дистилляции: коды ошибок, номера договоров, «ПЦФ 24-26» находятся, даже если дистилляция их не сохранила.
  • Vector (HNSW) — парафраз без общих слов; запрос на online-пути оборачивается в Instruct-префикс Qwen3-Embedding (см. раздел 03), документы на ingest — без него.
  • IDF-фильтр на ingest — филлер не доходит до базы и не портит выдачу; политика версионирована и обратима, raw хранится.
  • Age decay + superseded_by — новее побеждает при равных; замещённые версии исключены по умолчанию.
rrf(d)   = Σ_lists  1 / (60 + rank_list(d))
decay(d) = exp(-0.005 · age_days(d))          -- полураспад ≈ 140 дней
score(d) = rrf(d) · (0.7 + 0.3 · decay(d))
-- top-20 → merge по source_id → hydrate соседних unit_ord → top-10
-- LLM-reranker включать только после замера на eval-наборе из query_log

10 · Отказы

Как это ломается и что тогда

  • vLLM занят backfill'ом / лежит → инкрементальные задачи имеют приоритет; поиск работает всегда — online-путь от vLLM не зависит.
  • Воркер упал на 4 000-м файле → jobs в статусах, продолжение с места падения; watermark инкрементальных не сдвинут — дочитается.
  • Воркер умер с job в processing → lease_until истекает, job автоматически возвращается в очередь; ничего не зависает навсегда.
