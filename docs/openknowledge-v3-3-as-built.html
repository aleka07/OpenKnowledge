02 · Offline-конвейер

Путь файла: из папки в базу, без участия человека

Nextcloud «ПЦФ 24-26» → [rclone, 5 мин] → зеркало на gx10-1 → [ingest-таймер, 15 мин]
  → sha256 (дубль? — только путь в source_objects, работы ноль)
  → копия в raw store (оригиналы неприкосновенны, всё производное пересчитываемо)
  → job в очередь (prio: readable 5 → scan 10 → image 20; inbox = 0)
воркер ×3 → normalize (таблица ниже) → converted.md в raw store
  → чанки (по заголовкам, ≤3500 симв.; фильтра длины для документов НЕТ — policy v3)
  → паспорт документа (1 LLM-вызов: doc_type/title/year/authors/basis → meta всех строк)
  → distill ×N (семафор 16, JSON по схеме, ядовитый чанк → 2 ретрая → raw-passthrough)
  → embed (батчами по 64, БЕЗ Instruct-префикса, обрезка до 1536 + нормировка)
  → upsert в evidence (идемпотентно; изменённый файл → старые строки superseded_by)

Маршрутизация форматов (выбрана замерами на реальных файлах)

ФорматПутьПочему
PDF с текстомdocling-serve → фоллбэк MarkItDowndocling достаёт заголовки (25 против 0) → чанки по секциям; фоллбэк — чтобы ingest не зависел от контейнера
docx / xlsx / pptx / docmMarkItDowndocling здесь хуже: раздувает таблицы пробелами в 2.8×, теряет заголовки pptx, медленнее в 5–60×
.doc / .rtf (старые)LibreOffice headless → docx → MarkItDownMarkItDown их не читает; обязателен LANG=C.UTF-8 — иначе soffice не открывает кириллические пути
PDF-скан (<100 симв/стр)pymupdf → PNG постранично → Qwen3.6 vision → merge с маркерами <!-- page N -->docling-OCR выдаёт транслит-кашу на кириллице; vision-модель читает чисто. Битая страница ретраится отдельно, документ не ждёт
Фото (jpg/png/heic)name-only строка: имя + путь папки«найди фото с Иссыккуля» работает по имени; содержимое фото — отложено сознательно
Прочее (zip, fbx, exe…)skipped с причиной—
Политика фильтра v3 — одно правило. Разговорный контент (эпизоды митингов, когда появятся) фильтруется; документы — никогда. Сохранённый человеком документ — сигнал по умолчанию, даже одностраничный чертёж: его убил бы порог длины, а по IDF-логике он концентрат редких токенов. Отбрасывается только вырожденное (ни одного осмысленного слова). Если из файла совсем нечего взять — он всё равно индексируется строкой «имя + папка + что распозналось».
03 · Хранилище

Одна база, две идентичности файла

ТаблицаЧто хранит
evidenceединица знания: чанк/whole + артефакт дистилляции + embedding(1536) + tsv + meta (паспорт, люди, системы) + occurred_at + superseded_by. UNIQUE(source, source_id, unit, unit_ord)
raw_objectsфизический blob: sha256 → путь в raw store, mime, kind. Дубль в 10 папках = 1 строка
source_objectsвхождение: (source, путь/id) → какой blob сейчас за ним. Переименование не трогает blob; изменение содержимого → superseded_by у старых evidence
ingest_jobsочередь: статусы pending/processing/done/failed/skipped, приоритеты, ретраи с backoff, lease против зависших воркеров, filter_policy
api_tokens, query_loghash токенов (выдача insert, отзыв update) · кто, чем, что искал — аудит и будущий eval-набор
evidence_v (view)для SQL-тулзы: без embedding/tsv (мегабайты), паспортные поля подняты в колонки. Доступ — ролью okb_ro, которая физически видит только evidence_v / raw_objects / source_objects

Паспорт: doc_type из закрытого словаря (paper · report · contract · proposal · invoice · order · certificate · presentation · instruction · letter · note · other) — constrained decoding не даёт модели выдумать «papers». Расширение словаря = правка одной строки кода через человека, не runtime-механизм. year — из содержимого (DOI/шапка/дата подписания), НЕ из mtime; поле basis говорит, откуда взят атрибут. occurred_at (= mtime) остаётся отдельно — на нём decay свежести.

04 · Online: MCP

Шесть тулз — гибкий инструментарий, не «поисковик»

ToolКласс вопросаКак работает
search(q, sources?, k?)смысл: «где обсуждали X», «что мы знаем про Y»гибрид: vector top-40 + FTS top-40 → RRF(60) → decay свежести; superseded исключены; запрос оборачивается в Instruct-префикс (документы при ingest — нет, асимметрия Qwen3-Emb)
query_evidence(sql)полнота: «перечисли ВСЕ», «сколько», «сгруппируй»read-only SELECT по evidence_v; защита: только SELECT/WITH + роль без прав записи + таймаут 5 с + потолок 200 строк. Слепые зоны видимы: WHERE doc_type IS NULL
get_raw(raw_ref, offset?)дословно: цитата, таблица, страница сканадля бинарных оригиналов отдаёт converted.md (у сканов — с маркерами страниц)
search_meetings / search_docsто же, с фильтрами источникаобёртки над search
recent(source?, days?)что нового проиндексированолента по indexed_at
add_note(title, text, sources)запись — единственная, с гейтом через человекакросс-документная находка → .md в kb-data/notes/ → штатный конвейер, source=note, автор из токена. Оригиналы тронуть невозможно; исправление = новая заметка
score(d) = RRF(d) · (0.7 + 0.3 · exp(-0.005 · age_days))   -- полураспад ≈ 140 дней
-- замер: поиск 0.3–1.0 с end-to-end при цели < 2 с
Решение против вики. База работает на голых файлах; слоя «поддерживаемых страниц» нет намеренно: большой вики-блоб тянется в каждый ответ (те самые 127k токенов), окаменевшая ошибка ЛЛМ светится везде, актуальность требует дисциплины. Вместо этого: дорогой кросс-документный вывод (например, разбор фальшивых DOI) сохраняется лениво через add_note — заметка размером с чанк, с источниками и автором, конкурирует в выдаче наравне с документами, замещается новой.

06 · Грабли

Что уже сломалось и как закреплено

  • vLLM молча игнорирует guided_json (устаревший параметр) → модель отвечала markdown'ом вместо JSON. Схема навязывается через стандартный response_format: json_schema.
  • Qwen3.6 — reasoning-модель: без enable_thinking: false весь бюджет токенов уходит в размышления, content возвращается пустым.
  • pgvector HNSW ≤ 2000 измерений, у Qwen3-Emb-8B — 4096 → matryoshka-обрезка до 1536 c перенормировкой; тег модели в evidence: …@1536.
  • Ядовитый чанк валил документ на 627 чанков (модель зацикливалась внутри JSON-строки) → изоляция на уровне чанка: 2 ретрая → passthrough сырого текста с пометкой в meta.
  • soffice + кириллические пути: под POSIX-локалью «source file could not be loaded» → LANG=C.UTF-8 зашит в код.
  • docling на кириллических сканах — транслит-каша даже с ocr_lang=ru → сканы только через vision Qwen.
  • В архиве лежит RTF, переименованный в .doc, и файлы без расширений — такие честно падают в failed/skipped с причиной, конвейер не останавливается.
