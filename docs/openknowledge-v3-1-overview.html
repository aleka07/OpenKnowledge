01 · Принципы

Шесть решений, которые не пересматриваем

Данные живут там, где рождаются

Команда не меняет привычки. Коннекторы сами забирают данные из источников.

Одна таблица — один контракт

Любой источник приводится к схеме evidence. Новый источник = скрипт, а не подсистема.

Offline ≠ Online

Ingest медленный, может падать и догонять. Поиск отвечает < 2 s и не зависит от vLLM.

Оригиналы неприкосновенны

Raw store первичен. Всё производное — markdown, артефакты, эмбеддинги — пересчитываемо.

Идентичность файла = хэш содержимого

Дубликат в десяти папках — один объект и десять путей в метаданных, обрабатывается один раз.

Ни у кого нет чёрного хода

Claude Code, скрипты, будущие UI — все ходят через одни MCP-тулзы с токеном.

03 · Жизненный цикл

Два конвейера, одна точка встречи

OFFLINE — минуты/часы/сутки, можно падать и догонять
syncинкрементально по watermark — или backfill-очередью при массовой загрузке архива
dedup + rawSHA-256 содержимого; уже видели — добавили путь и вышли; новое — в raw store
normalizeбинарные форматы → markdown (MarkItDown); PDF-сканы → постранично через VLM
distillLLM превращает единицы текста в артефакты: question / summary / resolution / systems
embed + upsertэмбеддинг нормализованного content, идемпотентная запись в evidence
◈ POSTGRES / evidence — единственная точка интеграцииpgvector + GIN
source · source_id · unit   -- откуда, что, какой гранулярности (whole/episode/chunk/page)
content · embedding · tsv   -- нормализованный текст + два индекса поверх него
meta · raw_ref              -- участники/проект/пути + дорога к оригиналу
occurred_at · superseded_by -- свежесть и замещение — вся темпоральная модель
ONLINE — < 2 s, без тяжёлых LLM, живёт при лежащем vLLM
hybrid retrieveпараллельно vector top-40 + full-text top-40, фильтры по source / meta
fuse + decayRRF(60) + множитель свежести; superseded-строки исключены по умолчанию
hydrate + respondсоседний контекст + raw_ref → evidence-строки клиенту через MCP

06 · Roadmap

Вертикальный срез, потом ширина

Неделя 1
Срез: митинги end-to-end

Схема БД, воркер транскриптов, дистилляция эпизодов, MCP + Caddy на Contabo, первые токены. Один источник, весь путь.

Недели 2–3
Backfill архива 9k

Инвентаризация + дедуп → очередь → читаемые документы за первые сутки-двое, сканы фоном через VLM. Детали — Doc 2.

Неделя 4
Живые источники + качество

Drive и Obsidian инкрементально. Eval-набор из query_log, подкрутка decay и фильтров по замерам.

Фаза 3
Код + кастомные источники

Инкрементальный пайплайн для репозиториев; плагин-скрипты для CRM и клиентских БД.

Отложено сознательно — и при каком сигнале вернуться

  • Граф сущностей / relationship index — когда meta-фильтров перестанет хватать.
  • Полная темпоральная модель — когда decay + superseded_by начнут ощутимо ошибаться.
  • Поиск по содержимому фотографий — в backfill фото индексируются только по имени и пути.
  • Разделение на отдельные stores — когда упрётся Postgres; логические границы уже проведены.
  • OAuth / SSO, свой web UI — при внешних или не-Claude-Code пользователях.
